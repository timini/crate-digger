# Supported audio formats

Crate Digger decodes audio with [symphonia](https://github.com/pdeljanov/Symphonia) 0.6, a pure-Rust decoder, so every platform decodes the same formats in the same way. A format is listed as supported only if it has a passing decode test over a synthetic fixture. The fixtures are two-second 440 Hz tones generated by `scripts/gen-fixtures.sh` and committed under `crates/audio/tests/fixtures`.

| Extension | Codec | Fixture | Test (`crates/audio/tests/decode.rs`) |
| --- | --- | --- | --- |
| `.wav` | PCM, 16-bit little-endian | `tone.wav` | `decodes_wav` |
| `.aif`, `.aiff` | PCM, 16-bit big-endian | `tone.aiff` | `decodes_aiff` |
| `.flac` | FLAC | `tone.flac`, `other-stereo.flac` | `decodes_flac`, `stereo_48k_reports_channels_and_rate` |
| `.mp3` | MPEG-1 Layer III, 128 and 320 kbps | `tone.mp3`, `tone-320.mp3` | `decodes_mp3` |
| `.m4a`, `.mp4` | AAC-LC | `tone.m4a` | `decodes_aac_in_mp4` |
| `.m4a`, `.mp4` | ALAC | `tone-alac.m4a` | `decodes_alac_in_mp4` |
| `.ogg` | Vorbis | `tone.ogg` | `decodes_ogg_vorbis` |

`every_advertised_extension_has_a_fixture` fails if an extension is added to `SUPPORTED_FORMATS` without a decode test.

## Not supported

These are not indexed during import:

- Opus, WMA, APE, WavPack and DSD.
- HE-AAC (AAC+) has not been tested; files may decode as AAC-LC without spectral band replication and sound dull. It is not advertised.
- Compressed AIFF (AIFF-C) has not been tested.

## Damaged files

Files that cannot be decoded stay in the library with an "Unreadable" status and an explanation. Their metadata and ratings are kept. `corrupt.mp3` (random bytes) and `truncated.flac` (the first 200 bytes of a FLAC file) cover this in the tests.

## Playback

Playback decodes on a background thread into a two-second ring buffer and resamples to the output device's rate, using rubato's FFT resampler, so the app never changes the system sample rate. `crates/audio/tests/playback.rs` checks that no underruns happen while two threads decode continuously, which is more than the scheduler allows for analysis. To measure on real hardware:

```sh
cargo run --release -p cd-audio --example playback_harness -- <file> [seconds] [load_threads] [volume]
```

Measured on the development machine (Apple Silicon, 10 cores, macOS, built-in output at 44.1 kHz): zero underruns over 6 s with 2 and with 10 background decode threads, including 48 kHz to 44.1 kHz resampling. Results on the release reference hardware go in the release validation report (#21).
